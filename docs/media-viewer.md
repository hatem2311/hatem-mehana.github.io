# Media viewer

The owner subsequently authorized YouTube previews for Implant Mission and King of Strategy. Their existing full video links are used with the official IFrame API, muted before play, inline, with 30–38 seconds for Implant Mission and 15–23 seconds for King of Strategy. Loop playlist parameters and a current-time boundary check keep the preview in its selected interval. All three supported projects now get previews in All Projects too. The API loads only when a YouTube card becomes active; no remote video is downloaded or converted. One preview is active at a time, rotating every ten seconds when several supported cards are visible. Exiting the viewport, hiding the tab, changing filters or enabling reduced motion destroys the YouTube player. API/network errors, autoplay-blocked events and a 15-second player timeout retain the poster and full-video link.

YouTube integration was tested with controlled API responses for mute-before-play, interval/loop parameters, lazy loading, player disposal, filters and failure cases. Both real YouTube players reached the playing state in local Edge. External service policies and rendering may vary; no unrestricted cross-device playback guarantee is made. `youtube-preview-live-results.json` records the separate live check. Remaining four projects (Horror Home, 3D Tic Tac Toe, Lanterns Ninja, Roblox Maps) have no existing video source and remain Pending. Task 30 stays In progress for that full scope.

Reference: [YouTube IFrame API](https://developers.google.com/youtube/iframe_api_reference) and [player parameters](https://developers.google.com/youtube/player_parameters). The 200px minimum player height is reserved from initial render, preventing layout movement.

The local-video part of task 30 is implemented for Azooma. The existing `images/Azooma/827089c520bfe9f758c14cf58089a032.webm` is a verified playable 6.966-second, 780×438 gameplay clip (606084 bytes). `previewVideo` in its editorial project source enables the local card preview; projects without a local or YouTube preview configuration keep their images.

`js/card-preview.js` loads near the viewport and automatically plays only while at least 25% visible. Playback is muted, looped and inline, with only one preview active. Leaving the screen, hiding the tab or enabling reduced motion pauses it. Reduced motion initially prevents loading; blocked autoplay and decode/network errors retain the existing poster and a clear full-video link. The link is separate from View Details, supports mouse/Enter/touch and opens the existing full YouTube video. Fixed 16:9 dimensions preserve the three/two/one card grid. Static HTML retains the poster and both links without JavaScript.

Checks: `node tests/card-preview.cjs` verifies actual advancing frames and wraparound, muted/loop/inline properties, deferred requests, offscreen/hidden pause, live reduced-motion changes, mouse/keyboard/touch destinations, denied autoplay and failed-file fallback. Visibility-change logic is exercised with a controlled hidden-state event; physical mobile/browser policy checks remain within task 32's existing Pending scope.

The homepage includes an existing featured project's gameplay preview before the three featured cards. `js/home-video.js` creates an iframe inline only when Play is activated, without an autoplay parameter; the player and an external fallback link remain usable at a fixed 16:9 ratio. Static HTML provides the same preview as a direct video link. Keyboard, mouse and touch activation and failed-player recovery are covered by the browser suite.

The gallery progressively adds a caption, current item count, Previous/Next controls and a viewport-sized native dialog. Left/Right navigate while focus is inside the viewer or thumbnail region. Escape closes the dialog and returns focus to the opening button. Native modal behavior keeps background controls inert. Closing or changing an item destroys the current iframe; a new video starts only after pressing Play.

Edit `galleryCaptions` as an optional array aligned with `gallery` in the project source. The schema rejects mismatched counts and empty descriptions. Existing case-study figure captions are reused when their image matches; other images get a project-specific screenshot label. Captions are also used as main-image alt text. No undocumented design history is inferred.

Image width/height come from the responsive manifest. The main viewport has a stable height and uses `object-fit: contain` for portrait and landscape images. Fullscreen reserves the inline viewer's space and uses the same preview node, avoiding duplicate players. This is a fullscreen dialog within the browser, so it also works when the browser Fullscreen API is unavailable.

The video viewer has a permanent Watch on YouTube link. Error events and trusted YouTube player messages show a retry control; after ten seconds without a player response the viewer offers the same fallback. Messages must match both the iframe window and a permitted YouTube origin. A timeout cannot prove whether an external video is unavailable, so the message also covers a player that is not responding.

`js/gallery.js` owns the media selection; `js/media-viewer.js` owns the enhancement lifecycle. Rerendering aborts listeners, clears timers, disconnects the observer and removes the dialog. Generated static pages keep their original readable screenshot and video link when JavaScript is unavailable.
